Case 01 · Creative Development

Wisionary Lab: o site é a prova.

Como transformei o site de uma agência que vende "presença digital com lógica de negócio" em uma demonstração técnica ao vivo: 3D interativo em Three.js, conteúdo 100% gerenciável em WordPress e performance tratada como requisito de conversão.

S · Situação

O site da agência é a primeira entrega.

A Wisionary Lab vende uma tese simples e exigente: antes de você dizer uma palavra, o cliente já decidiu. Sites deixam de ser folders estáticos e passam a ser canais de aquisição, com estratégia, copy forte e design que converte.

Isso cria um problema que nenhum cliente teria: o próprio site da agência é auditado por quem vai contratá-la. Um LCP lento, uma animação que engasga no celular ou um formulário confuso não seriam só um bug; seriam a refutação pública do discurso de venda.

Se a agência promete presença com lógica de negócio, o site dela precisa ser o case mais difícil do portfólio, não o mais fácil.
T · Tarefa

Três forças que puxam para lados opostos.

O briefing técnico se resumia a equilibrar três requisitos que, em projetos comuns, competem entre si:

1. Performance brutal

SEO e conversão dependem de Core Web Vitals no verde em celulares intermediários com 4G, não em um MacBook com fibra. O orçamento definido no início: LCP < 2,5s, INP < 200ms, CLS < 0,1 e JavaScript crítico abaixo de 100 KB comprimido.

2. Impacto visual em 3D

Elementos tridimensionais dinâmicos em Three.js, reagindo ao scroll e ao ponteiro, para materializar a ideia de "visão" da marca. WebGL é, por natureza, o recurso mais caro de uma página.

3. Autonomia de conteúdo

O time precisa editar textos, serviços, cases e FAQ sem depender de desenvolvedor e sem que uma edição quebre o layout. Isso descarta page builders pesados e exige um modelo de conteúdo pensado.

Meu papel: desenhar a arquitetura do tema WordPress, implementar toda a camada de interação e garantir que as três forças coexistissem em produção.

A · Ação

Engenharia a serviço da narrativa.

WordPress/PHPThree.jsSass

WordPress como plataforma de conteúdo, não de layout

Em vez de um page builder, construí um tema sob medida em PHP, no qual o design é código e o conteúdo é dado. Cada seção da home (Gap, Serviços, Processo, Cases, Objeções, FAQ, Contato) virou um template part isolado, alimentado por campos estruturados.

  • Modelo de conteúdo explícito: serviços, cases e perguntas frequentes como tipos de conteúdo próprios, com campos tipados (título, tier, descrição, CTA) em vez de um editor livre.
  • Edição segura: o editor altera texto e ordem; tipografia, espaçamento e responsividade continuam governados pelo tema. Ninguém "quebra o site" ao atualizar um serviço.
  • Enxugamento do core: remoção de emojis, embeds, jQuery no front e estilos de blocos não usados; assets enfileirados apenas nas rotas que os consomem.
  • SEO no template: hierarquia de headings garantida pelo PHP, dados estruturados e metas gerados a partir dos próprios campos.

Three.js sem destruir o scroll

A regra foi tratar o 3D como aprimoramento progressivo: o conteúdo e o LCP nunca esperam pela cena. O WebGL entra depois, só se o dispositivo aguentar, e sai de cena quando não está visível.

  • Fora do caminho crítico: a biblioteca é carregada via import() dinâmico após o load e em requestIdleCallback. O HTML pinta primeiro; o 3D faz fade-in por cima.
  • Um único render loop: um requestAnimationFrame central, pausado por IntersectionObserver quando a cena sai da viewport e por visibilitychange quando a aba fica oculta. Zero GPU gasta com o que ninguém vê.
  • Scroll desacoplado: o listener de scroll só grava um valor (passive: true); quem lê e interpola é o loop. Nada de cálculo pesado dentro do evento.
  • GPU sob controle: devicePixelRatio limitado (1,5 no mobile), powerPreference: "low-power", antialias desligado em telas densas e contagem de partículas reduzida em telas pequenas.
  • Assets 3D enxutos: geometria procedural sempre que possível; quando há modelo, glTF com compressão Draco/Meshopt, texturas em potência de 2 e reutilização de materiais e geometrias para minimizar draw calls.
  • Saídas de emergência: sem WebGL, com prefers-reduced-motion ou Save-Data, a cena simplesmente não carrega, e um gradiente estático ocupa o lugar.
// render loop único, pausado fora da viewport e com a aba oculta
let rafId = null, visible = true;

const render = () => {
  scroll.current += (scroll.target - scroll.current) * 0.08; // lerp
  mesh.rotation.y = scroll.current * 0.002;
  renderer.render(scene, camera);
  rafId = requestAnimationFrame(render);
};

const start = () => { if (rafId === null && visible && !document.hidden) rafId = requestAnimationFrame(render); };
const stop  = () => { cancelAnimationFrame(rafId); rafId = null; };

new IntersectionObserver(([e]) => { visible = e.isIntersecting; visible ? start() : stop(); }).observe(canvas);
document.addEventListener("visibilitychange", () => (document.hidden ? stop() : start()));
addEventListener("scroll", () => (scroll.target = scrollY), { passive: true });

CSS: mobile-first, orientado a tokens

A interface foi escrita em Sass estruturado, com a marca codificada em tokens e componentes que não sabem em qual página estão.

  • Camadas claras: tokens → base → layout → components → sections → utilities. Cada camada só consome a anterior, o que elimina guerras de especificidade.
  • Tipografia fluida: escalas com clamp() substituem dezenas de media queries; o título cresce com a viewport sem saltos.
  • Mobile-first de verdade: o CSS base é o celular; breakpoints só adicionam. Isso reduz o CSS que o mobile precisa interpretar.
  • Animação barata: apenas transform e opacity animados, para manter tudo na thread de composição e o INP baixo.
  • CLS zero por design: mídia com dimensões declaradas, fontes com font-display: swap e métricas compatíveis, canvas posicionado em camada absoluta.
R · Resultado

Uma vitrine técnica que também vende.

O site virou o argumento de venda mais forte da agência: em vez de dizer que entrega performance e design que converte, ele demonstra isso durante a visita. A narrativa da home conduz a um único CTA: o diagnóstico gratuito.

Aprendizados
  • 3D é narrativa, não decoração. Cada elemento tridimensional precisa reforçar uma mensagem da copy; caso contrário, é custo sem retorno.
  • Orçamento de performance antes do layout. Definir limites no dia 1 transforma "o site está pesado" em uma decisão objetiva de projeto.
  • Autonomia é arquitetura. Um CMS só dá liberdade ao cliente quando o modelo de conteúdo impede que ele quebre o design.
